# U9.1 TableProvider fixture boundary

This is an independently authored, transport-neutral contract and deterministic fixture suite. It has no activation function, tool window, runtime/session imports, UI, native transport or new dependencies. It does not ship a data explorer. No vendor implementation was copied. Backend keys are opaque strings (for example `fixture/neutral`), never an R/Python backend union.

`contract.ts` defines the JSON domain, `validation.ts` copies validated unknown envelopes, `fixture.ts` implements the fixture provider, and `cache.ts` supplies its shared LRU budget. Consumers must validate incoming requests and responses with trusted limits. Responses must match the expected complete identity, request id, offset, projection order and dimensions. Read fresh state with the current handle after invalidation; fetching state does not revive a revoked handle.

Cells preserve integer and fixed-point decimal strings, including decimal scale. Float `finite` accepts finite numbers except negative zero; `nan`, `+inf`, `-inf` and `-zero` encode the other cases explicitly. JSON serialization must happen after validation, since JSON itself destroys nonfinite numbers and negative zero. Missing codes distinguish Python None/pandas.NA/NaT, R typed NA, SQL NULL and all 28 SAS numeric missing codes (`.`, `._`, `.A`–`.Z`). SAS codes are inert data. IEEE NaN uses the float tag, separate from R NA. Empty text and integer zero are ordinary values.

Temporal ticks are signed integer strings with explicit resolution and timezone (null means no asserted zone). Date/timestamp ticks use the Unix 1970-01-01 origin; time uses local midnight; duration is elapsed ticks. No date formatting, timezone conversion or comparison is implemented. Adapters must convert source epochs losslessly (including SAS 1960), and must not invent a zone for naive values. Category codes reference a dictionary id and revision; schema advertises dictionary size/order. Dictionary-level paging and label resolution are deferred: a renderer must not interpret a code against another dictionary revision. Nested cells have only bounded summaries and sizes, no recursive child evaluation. Binary is a preview, not a complete binary payload. Errors/unsupported are distinct from missing values.

Columns use stable ids plus source ordinals. Display names can be duplicate or empty. The intentionally mixed fixture columns advertise `unknown` logical type; column 9 advertises a revisioned category dictionary. Column 999 emits a truncated Unicode preview. The fixture describes 1,000,000 rows x 1,000 columns without creating them. It synthesizes only requested cells, stopping on a payload byte refusal; the complete encoded response is checked again. An oversized response rejects the entire page, never returns a silent partial page. A preview's truncation flag refers to that value, not to a partial dataset. Row counts/offsets are canonical unsigned decimal strings of at most 128 digits. Only `checkedIndex` converts them to local numbers after a caller-supplied safe bound; huge valid offsets beyond this fixture return empty pages while preserving the requested offset.

## Fixture-only authority and lifecycle

The caller supplies a host authorization callback separately from all envelopes. HostScope identifies project incarnation, window, owning document, kernel generation, object revision and viewer. These are opaque ids, not filesystem paths, names, expressions or lookup instructions. A provider instance resolves its issued handle only after checking host authority and every scope field; there is no global bare-object lookup. Tokens are predictable fixture counters. Copying a valid token is possible. This is **fixture-only authorization, not a production security claim**.

The simulated trusted host owns `revoke(scope)`; do not expose it as arbitrary client-controlled IPC. Lifecycle notifications must revoke each affected scope on trust loss, project/document/window close, kernel stop/restart/death or object removal. Revocation releases resources even after the authorization callback denies access. Close is idempotent for an already absent handle with matching caller scope. Revocation does not establish a permanent deny list: the host must keep denying an obsolete scope when a later open is attempted.

Every operation checks current authorization and handle ownership. Awaited schema/page work checks them again before generating/returning data. Requests are snapshotted, so caller mutation cannot change admitted work. Each handle has its own query epoch/projection. Projection changes cancel pending work and evict its cache; unsupported operations change nothing. Refresh advances data/schema revisions and cancels/evicts all existing viewers of the same scoped object, preserving independent projections. Other object revisions and sessions are isolated. Revisions are invalidation markers, not transactional runtime snapshots.

AbortSignal, close, revoke, refresh and query changes abort pending work. The fixture races cancellation against its test seam, settling even if the seam ignores the signal. An eventual transport adapter must actually release backend jobs/subscriptions and honor cancellation; this fixture cannot prove that. Duplicate in-flight request ids are rejected. No timers, background polls, timeouts, kernel or network work are created.

## Bounds and accounting

| Bound                                                | Default / hard maximum     |
| ---------------------------------------------------- | -------------------------- |
| Page rows                                            | 256 / 256                  |
| Page projection / schema columns                     | 32 / 32                    |
| Encoded complete response                            | 2 MiB / 2 MiB              |
| UTF-8 cell preview / column display name             | 4 KiB / 4 KiB              |
| View / provider / shared retained-cache budget       | 16 / 64 / 64 MiB           |
| Open views per provider                              | 16 / 128                   |
| In-flight schema + page requests per view / provider | 2 / 8 (hard maxima 2 / 16) |

Config rejects zero, nonfinite, fractional, negative or over-limit bounds and invalid budget relationships. Smaller positive bounds may intentionally make some responses impossible; those operations explicitly fail. Identifiers/numeric strings have a 128 UTF-8 byte cap. Other envelope arrays and tags have independent strict limits. Validators reject extra enumerable fields and malformed shapes. They accept plain JSON data, not hostile JavaScript objects with accessors/proxies.

The host must inject **one FixtureCacheBudget shared by all providers in its simulated broker**. Each entry stores a validated JSON wire string rather than retaining a decoded cell graph. Accounting charges UTF-16 wire length + UTF-8 wire bytes + UTF-16 key length + a fixed bookkeeping reserve. LRU eviction enforces view, provider and shared totals. This is conservative retained-payload accounting, not an exact JavaScript heap measurement. Decoded consumer objects and transient validation/serialization copies are outside retained-cache accounting; dimensions, byte refusals and in-flight caps bound provider work. A page too large for the cache is returned uncached. Close/revoke release its entries; query/refresh invalidate them. Cached replies are revalidated and correlated with the new request id. No wall-clock latency, native memory or performance acceptance is claimed.

## Deferred gates

Only bounded paging, schema paging and projection are supported. Sort/filter/profile/export return explicit capability results. QuerySpec describes bounded sort keys and a single typed equality predicate for capability negotiation; no filter AST engine, source evaluation, local sort masquerading as full-data sort, profile jobs, streaming exports, dictionary loader, row keys/index metadata, nested expansion or full-data aggregates are implemented. ProfileRequest reserves dataset/filtered scope and requested kinds; there is deliberately no fake profile-result model.

U9.2 needs separate approval and owner coordination. Recommend **R Ark variable-to-explorer capability smoke first**, against the pinned public protocol and installed Ark, then select a bounded read-only adapter slice. A bounded Python pandas adapter is an alternative first slice if explicitly chosen: known concrete supported types only, no arbitrary repr/getattr/eval, no mandatory pandas install, and no replacement of existing ipykernel ownership. Neither adapter is started here. Real host-issued unforgeable capabilities, trusted window/project/document routing, execution/mutation invalidation, actual transport response framing/limits, real cancellation, dictionary/index metadata and runtime consistency must be verified there. Native GUI/accessibility/WebView performance acceptance and production grid work remain later gates. SAS transport/runtime/licensing and remote credentials require separate decisions.
